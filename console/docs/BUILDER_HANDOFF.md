## Delivered interface, not fabricated intelligence

The five navigation scopes, scoped search, category filters, record inspector, explicit fixture links, command router, brief, priority controls, local review flow, receipt export, quality controls, focus layout, pause, reduced motion and disconnected voice explanation work locally.

Every fixture is fictional. Some project names are recognisable, but their displayed status is illustrative. No backend or real account is contacted. A submitted command is either a local route or a search over the current scope. It is never executed as a shell command, unrestricted prompt or external action.

## Integration sequence

1. Keep the current console and existing `web/` application side by side. Introduce a same-origin, authenticated integration route only after inspecting the actual server routing, allowed Host/Origin policy and bearer/session handling. Do not relax CORS/Origin/loopback restrictions to make Vite convenient.
2. Create a separately tested adapter over the real service responses. The current `ConsoleSnapshot` fixture type is not a backend API. Do not simply rename its `mode` to live. Design an explicit connected-state union with loading, disconnected, denied, stale, revoked, error and partial states.
3. Obtain permitted scopes from the server. The demo's hard-coded scopes are not grants. Restrict records and counts before rendering. Avoid transient cross-scope data during fetches, races, inspector retention, logout or revocation.
4. Connect read-only notes and reviewed memory first. Keep note links separate from entity/claim relationships. Preserve stable identities, source revisions, exact provenance, claim review state, conflicts and invalidation. Never merge records because their display names match.
5. Connect conversation state and source-first answers. The command bar needs an explicit command/ask distinction. Show queued, generating, ready, withheld and failed states honestly. No generated content creates permission. Do not turn the sphere into a fictitious visualisation of a model's hidden reasoning.
6. Replace the local demo review flow only after its real backend counterpart is wired. Show the exact action, payload, scope, revision/hash, effect and expiry returned by the server. Obtain server-authorised approval. Recheck grants, revocation and idempotency server-side. A frontend reducer receipt is never a real action receipt. Distinguish proposed, approved, executing, result-known, failed and unknown outcome.
7. Connect the bounded existing Pulse routines deliberately. Do not add arbitrary scheduled prompts, shell commands or an implicit always-running host. Show the actual host lifecycle, freshness and failure state.
8. Add voice only as a separate measured adapter with explicit permission, visible recording, stop/cancel and interruption handling. Until then, preserve the truthful disconnected state and do not request microphone access.

## Sphere: preserve meaning as well as appearance

The fine particle field, thin spherical lattice and orbit lines are decorative materials. They have no real-world records behind them. The larger record nodes and separately rendered explicit links come from the typed data. The inspector is the canonical explanation of what a relationship means.

Do not count decorative vertices as memory records, expose guessed confidence scores or describe bloom as live inference. Do not replace the shader scene with a looping video or an image of the reference. Stable node layout should eventually be derived from stable record IDs, with bounded clustering/level-of-detail for large authorised data sets. The current small-fixture layout is not a large-graph engine.

Keep standard text, inputs and operational panels in accessible DOM. Do not convert the entire app into a canvas. Record navigation must remain possible without GPU rendering and without dragging a 3D object.

## Material and motion constraints

Use a genuinely black background with shallow graphite surface differences. Amber is sparse and semantic, not a perimeter glow on every panel. Avoid neon palettes, decorative military typefaces, stock sci-fi textures, office photographs and large permanent marketing text during active work.

The graph has restrained slow movement, delicate edges, soft star cores and controlled bloom. Pause and OS reduced motion must still work. Hidden documents should not continuously animate. Avoid React state updates on each animation frame. Dispose geometries, materials, composers and controls on replacement/unmount.

Use the high-quality profile for the target desktop and keep the balanced option. Measure actual frame times, renderer memory and behaviour on named devices before promising 60 fps, battery efficiency or mobile readiness. A software Chromium rendering check proves that the shaders ran, not the performance of a physical GPU.

Preserve the current brain tests and add browser-to-real-server tests for the new route.

In addition, compare actual application screenshots against the approved design at 1648 x 928 and normal laptop widths. Test loading, empty, failed and disconnected states. Verify keyboard access, focus order, reduced motion, readable text, unavailable WebGL, session reset and zero unintended external requests.
