# Source permission defaults and migration

3 October 2026. Requirements SYS-001/M02 and MEM-009. New workspaces, including
synthetic ones, use explicit grants. Normal provisioning of a person, device or
source does not grant read, model, sync, connector or inbox access. `init` grants
the synthetic demo owner read/model and the synthetic demo reader read over the
selected demo source only; it grants neither writing nor future sources.

Opening a pre-migration database records a **one-time compatibility snapshot** of
its pre-existing credentials/sources and their bounded expiries. Reopen cannot
expand that snapshot. Newly provisioned credentials/sources cannot inherit legacy
access. Existing revocations, expiry and strict-grant workspaces remain effective.
This is compatibility, not approval for a private pilot.

After stopping the host, an owner can run:

```
python3 -m alfred.desk migrate-grants --data-dir /path/outside/git
```

This makes ungranted access default-deny. To **explicitly retain recorded legacy
reads**, add `--preserve-legacy-reads`. Only active snapshot participants acquire
read grants; model egress, inbox writes, sync and connector imports are not migrated.
Existing explicit grants are preserved. The command uses the host lock, never
prints a key, checks the policy epoch and returns a receipt. Repeating an already
completed migration makes no additional grants. Pairing uses the existing explicit
one-time person enrolment; device review/approval histories remain credential-private.

The offline `legacy_scope=True` API argument is an explicit **synthetic historical
fixture**, rejected for non-synthetic workspaces and unused by normal provisioning.
Existing tests/evaluators which exercise the historical coarse policy now name that
fixture explicitly; their assertions remain. New default/migration regressions use
normal provisioning, including a database shaped like the pre-migration store.
Browser access-loss scenarios now revoke a read grant rather than expecting that
enabling explicit policy revokes the demo's deliberately granted reads.

Health's note/issue/job totals are permission-filtered; scanner totals no longer
reveal restricted sources. Reader mutation routes check role before consulting the
source catalogue. Graph, questions, approvals, jobs, exports and routines continue
through their common permission checks. New tests cover reopen, new people/sources,
read versus model/write purposes, expiry/revocation, migration choices/idempotence
and deliberate demo grants. Combined test evidence is in the final stage receipt.

Remaining: team/multi-owner administration, source-management catalogue policy,
shared person-history acceptance, encryption/key custody and selected private-pilot
approval. An owner can still administer source grants; administration is not source
read access. No device or private source is connected by this increment.
