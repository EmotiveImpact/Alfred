# Evidence selection and the synthetic project loop

3 October 2026. MEM-008/M06, INT-001/002, MEM-010 and UX-002.

Default lexical selection now requires at least half the meaningful question
terms (excluding summarise/summarize operation words) and at least half the best qualifying lexical score before adding a
keyword/link candidate. Weak matches and unrelated adjacent links no longer
fill the packet. Explicit selected-record context still leads and may include
bounded authored links; it grants no authority or truth. Reviewed current
statements keep their exact original support. No embeddings, graph service or
new model was installed. The previous selection remains an explicit internal
`baseline` comparator in the frozen evaluator, not a new HTTP privilege.

The unchanged 64-note/44-query fixture/answer-key hashes are recorded in
[relevance.json](relevance.json). A separate 12-note/18-query synthetic held-out
set was authored after the general lexical rule, before its first measurement.
Neither answer key enters retrieval requests; all packets are fetched before
scoring. Policies alternate ordering over three repeats. No model inference,
answer correctness, citation entailment or broad language generalisation is
claimed. The held-out set is small and from the same author, not an independent
production benchmark.

The precision/context improvement costs one frozen-set support and 2.71 points
of mean recall. Unsupported queries can still retrieve lexically similar text.
The raw per-query lists show this trade-off; an empty source packet is not an
answer-quality result. Timings are from this builder and these small fixtures.
Indexing scales, synonyms, languages, ranking and true answer evaluation remain
future measured work; no universal threshold or reasoning-quality claim follows.

Retrieval now captures and rechecks grant revision across the whole read. A
mid-read revoke refuses the entire packet, including selection/skipped metadata.
Regressions cover weak matches, unrelated links, unsupported named questions,
explicit focus, revocation during a read and frozen comparison compatibility.

The [connected-browser report](loop-browser-report.json) records 15 actual checks
for one fictional project: select, ask in source mode, inspect original text,
remember as a proposal, explicitly accept, correct by superseding, recall the
corrected value, forget both current and superseded values, reopen the local
server/database, then restore a backup taken before forgetting. Both values stay
forgotten; the user's source note remains. Chromium talks to the real same-origin
server/SQLite. No effects, provider, private data or model are involved. Server
reopen is distinct from the separate real SIGKILL test in A3.

This loop reproduced an additional defect: forgetting a superseded claim changed
neither graph tallies nor `dataRevision`, leaving its old value in an open
inspector after database deletion. The
[negative HTTP regression](forget-refresh-baseline.txt) failed before the fix. The revision now includes
this credential's private ledger IDs/versions/states, without exposing values or
another credential's claims. The unchanged browser deletion assertions then passed for
both forgotten rows. The broader browser run also found that a summarise operation word raised the floor in accumulated follow-up topics; it is excluded for relevance only, preserving the baseline. Connected/voice fixtures now name their topic for positive reads; the vague unfocused question is an explicit empty-packet check. The approved console design and rendering code are preserved.
