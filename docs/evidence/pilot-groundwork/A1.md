# Approval visibility regression

3 October 2026. Requirements MEM-009, SYS-001, ACT-001. Runtime baseline
`75947b8dd59a3161c862d2533850a032994778e2`; handoff `3fe9d25c87058499887ce4b0d8c90ccecc6954e9`
changes documentation only. The audit hypothesis is now reproduced, not merely inferred.

Three negative HTTP tests were run before changing runtime code. A different person
in the same workspace received a restricted inbox proposal's content, destination,
action ID and approval fingerprint through the console; the original desk action
listing also returned it. The originating credential still received that proposal
after its read grant was revoked. All three tests failed on the baseline.

Policy: draft/approval receipts are private to the originating **credential**, as
are the existing review ledgers. Even a read grant or a paired device does not share
drafts. Additionally, every bound source must still be readable to return a draft.
Approval/dispatch authority and read visibility are separate. A stale source revision
may leave an authorised receipt visible with `evidenceCurrent=false`; an inaccessible
source withholds the whole row, its fingerprint and its contribution to counts.

`action_visible` is shared by the console, original desk and local-core views.
Source permissions also cover project events, document listings, inspection and
acknowledgement. Desk evidence approvals and dispatch recheck read authority. Audit
views are credential-private and exclude restricted source/action subjects. Filtering
precedes pagination, and global workspace action totals are not returned.

Validation: `tests/test_console_api.py` passed 21 HTTP tests, including restricted
sources, separate people, grant revocation, granted reader/non-shared draft, owner
positive cases, source changes and revoked credentials. The first full backend run
had 1,116 passes and one old source-forget expectation to correct: cancelled actions
remain internally recorded, but removed-source actions must be withheld from reads.
The corrected lifecycle test checks both absence in the API and the stored cancelled
state. Full combined validation is recorded in the final stage receipt.

The visibility rule is deliberately conservative. No shared draft feature, person-wide
approval authority, team administration, encryption, private pilot or deployment is
claimed. Raw runtime logs are retained outside the checkout under
`/workspace/alfred-evidence/` and contain invented data only.
